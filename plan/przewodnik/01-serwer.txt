@@ server/sql/001_init.sql
> Najważniejszy dokument projektu: opisuje, co system w ogóle wie. Pięć tabel, a w nich reguły, których baza pilnuje sama, nawet gdy kod aplikacji ma błąd.
@19 ^
Komentarz tłumaczy dwie rzeczy. Plik wykonuje się sam przy pierwszym starcie pustej bazy w Dockerze, a identyfikatory to UUID. Numery 1, 2, 3 zdradzałyby liczbę kont i dałoby się je łatwo odgadywać.
@19 -- pin_hash
Tabela kont.

- `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`: unikalny identyfikator, który baza losuje sama, gdy go nie podasz.
- `email ... UNIQUE`: drugie konto na ten sam adres zostanie odrzucone przez bazę, nawet przy dwóch równoczesnych rejestracjach.
- `NOT NULL DEFAULT ''`: tekst nigdy nie jest `NULL`, więc w kodzie nie trzeba sprawdzać dwóch rodzajów pustej wartości.
- `pin_hash`: jest skrót, a nie sam PIN. Szczegóły w sesji 20.
- `timestamptz`: data z godziną i strefą czasową.
@19 CREATE TABLE pets
Tabela zwierząt.

- `REFERENCES users (id)`: klucz obcy, czyli zwierzę nie może należeć do nieistniejącego konta.
- `ON DELETE CASCADE`: usunięcie konta usuwa też jego zwierzęta.
- `CHECK (length(trim(name)) > 0)`: imię z samych spacji nie przejdzie.
- `CHECK (species IN (...))`: tylko trzy dozwolone gatunki.
- `numeric(5, 2)`: dokładna liczba, np. `17.50`. Waga nie ma błędów zaokrągleń jak zwykły float.
- `birth_date date`: może być `NULL`, bo wiek bywa nieznany. Sama data bez godziny.
- `is_lost` i `lost_message`: to one przełączają widok zawieszki na alarm.
@19 CREATE INDEX pets_owner_id_idx
Indeks to spis treści: „zwierzęta tego właściciela” baza znajdzie bez czytania całej tabeli. To zapytanie wykonuje się przy każdym wejściu do panelu, więc warto je przyspieszyć.
@19 -- Kod zawieszki jest
Tu kluczem głównym jest sam kod, bo to on jest zapisany na tagu i pod nim szuka serwer. `CHECK (code ~ '...')` sprawdza wyrażeniem regularnym format `XXXX-XXXX`. `ON DELETE SET NULL` zostawia zawieszkę po usunięciu zwierzęcia, ale już bez przypisania, a `pet_id = NULL` oznacza widok „tag nieaktywny”.
@19 -- „Jedno zwierzę ma
Indeks częściowy obowiązuje tylko dla wierszy z `is_active = true`. Zwierzę może mieć jedną aktywną zawieszkę i dowolnie wiele starych w historii. Reguły pilnuje baza, więc błąd w kodzie nie stworzy dwóch aktywnych kodów.
@19 -- Audyt
Historia skanowań. Świadomie nie ma tu adresu IP ani lokalizacji, bo to dane osobowe, które nie są potrzebne do działania. Tyle wystarczy, żeby odpowiedzieć właścicielowi: kiedy, jaką przeglądarką i czy to on sam.
@19 CREATE INDEX tag_scans
Indeks na dwóch kolumnach: najpierw kod zawieszki, potem data malejąco. Dokładnie w tej kolejności zapytanie pobiera historię, więc baza dostaje wiersze od razu posortowane.
@19 -- type: feeding
Szybkie zapisy po skanie. Tylko typ i czas, bo reszta funkcji spacerów została usunięta przy zmianie zakresu. `CHECK` ogranicza typ do dwóch wartości.
@19 CREATE INDEX activities
Ten sam pomysł co wyżej: lista aktywności jednego zwierzęcia od najnowszej.
